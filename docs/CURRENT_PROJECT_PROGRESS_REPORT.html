1. What problem is this project solving?

The project studies a team of simulated agents that must collect food from a grid and bring it back to a nest. Agents cannot send direct messages. Instead, they leave and sense two shared numerical fields—food pheromone and home pheromone. This indirect environmental communication is called stigmergy.

Research question in plain language: Can a team of agents learn to use local pheromone trails for cooperative work, and can a lightweight defense using only each agent’s own local experience reduce the impact of a small number of agents placing misleading food trails—without hurting normal work too much?

Key words explained

TermMeaning in this capstone
Grid environmentA simulated two-dimensional board divided into cells. Agents move north, east, south, west, or stay in one cell per step.
Pheromone fieldA grid of nonnegative numbers. Higher values mean stronger recent trail deposits. It is not real food, distance, trust, or a probability.
StigmergyIndirect coordination: an agent changes the environment and another agent later reacts to that change. No direct agent-to-agent messages are used.
PPOProximal Policy Optimization, a reinforcement-learning method. A neural network tries actions, receives reward, and gradually changes its action choices to improve expected reward.
Parameter sharedAll agents use the same neural-network weights. They behave differently only because their local observations differ; there is no separate network per agent.
Local observationWhat one agent can see near itself. The policy does not receive the whole map, attacker identity, attack timing, or a global food count.
CalibrationA controlled development experiment used to check whether a setting produces the required effect before building more work on top of it.
Held-out evaluationA final test on maps/attack types that were not used while choosing settings. It prevents tuning the project to the answers already seen.

Important scope boundary

This is a simulation project. It does not claim that robots or real ants have been tested. The goal is a reproducible research pipeline for a carefully defined grid-world study.

How one simulator step works

  1. All submitted agent actions are checked and movement is applied. Off-grid movement becomes a blocked stay.
  2. Agents deliver food at the nest or pick up food at a resource cell. When agents compete for limited food, a seeded order resolves it reproducibly.
  3. Honest agents deposit pheromone based on their resulting carrying state.
  4. In an attacked scenario, selected agents may add bounded false food pheromone at their actual current cell.
  5. Both fields are clipped to their shared maximum and then evaporate. Evaporation means each old value is reduced every step, so old trails gradually fade.
  6. The next 58-value local observation, shared reward, and episode status are produced.
Why the order matters: the attacker uses the same field cap and evaporation as honest deposits. It cannot write a huge permanent global signal or change rewards. This makes the threat model controlled and auditable.

3. Simulator and learning pipeline in detail

Clean eight-agent review simulator

The current review configuration uses an 8×8 grid with eight agents, two food patches containing a total of eight food units, and a 500-step limit. The agents sense only a 3×3 crop around themselves. The shared reward equals food delivered in that step; it is not multiplied by the number of agents.

Observation partWhat it containsWhy it matters
54 local-grid values3×3 cells × six channels: food present, nest, food pheromone, home pheromone, occupancy, boundary.Lets an agent react to nearby terrain, fellow agents, and trails without seeing the entire world.
4 own-state flagsCarrying, pickup this step, delivery this step, blocked this step.Lets an agent condition its behavior on its own task state.
Excluded informationAbsolute location, global food map, attacker ID, injected mass, attack event/time.Prevents an unrealistic “cheat” policy or defense.

Corrected home-pheromone mechanics

Empty agents moving outside the nest deposit a home trail that gets weaker with each successful movement since their last nest visit. A stationary or blocked empty agent outside deposits no home pheromone. A nest visit resets the counter. This removed an earlier artifact where an agent could build an unrealistically strong home hotspot simply by waiting outside.

With ordinary deposit 1, home-decay 0.95, and 10% evaporation, a first outward move leaves 1 × 0.95 × 0.90 = 0.855. A second outward move leaves 1 × 0.95² × 0.90 = 0.81225. Values from multiple visits can overlap, but all values are capped and fade over time.

What the PPO training result proves—and does not prove

A fresh review run completed 4,096 smoke transitions and 300,032 main-training agent transitions, with a saved checkpoint that reloaded correctly. This proves that the training pipeline operates, updates its parameters, and can be reproduced under the recorded configuration. It does not by itself prove useful coordination, robust trail following, or defense success.

In the eight-agent review diagnostic, deterministic actions delivered zero food. Stochastic actions had nonzero average delivery. Deterministic means always selecting the highest-probability action; stochastic means sampling from the learned action distribution. The difference is a limitation: the policy’s single “most likely” action is not yet reliably productive.

The older review checkpoint also showed equal mean clean and attacked team delivery (7.67 versus 7.67) and the fixed timeout baseline reduced delivery to zero. These are preserved negative results, not hidden failures.

4. Phase 2A: proving clean pheromone usefulness first

Before asking whether an attack damages pheromone-based coordination, the team needed to show that pheromone was useful in a clean task. Otherwise an “attack robustness” experiment would be meaningless: an attacker cannot reliably harm a signal the policy does not use beneficially.

The fair comparison

Full-input PPONo-pheromone PPORandom-action reference
Receives the ordinary 58-value local observation, including local food/home pheromone channels.Is trained separately using the same shape but with only the 18 local pheromone entries zeroed during both training and evaluation.Uses seeded random actions on the same development maps.

The no-pheromone comparison is stronger than simply hiding pheromone after training: it tests whether a policy trained without those channels performs differently under the same task. The Phase 2A rule required the full-input policy to beat both comparisons for all three training seeds.

Earlier negative and mixed results were retained

Candidates A–I explored several development-only environments: larger/repeated-retrieval tasks, simpler maps, slower evaporation, distant food clusters, shorter deadlines, and more training time. Some seeds were promising, but none passed the all-three-seed strict rule. This is good research practice: the records preserve failed hypotheses instead of presenting only the best run.

Candidate J passed the clean development gate

Candidate J kept the long scout-and-follow task and changed only food capacity from 30 to 50 units per patch. It used a 12×12 grid, four agents, two distant adjacent food cells, an 1,100-step horizon, and slow 2% field evaporation. Six fresh PPO runs (full/no-pheromone × seeds 7, 17, 27) plus three random references were completed.

5. Phase 2B: attack calibration and honest negative findings

The attack model

At episode reset, one of four agents (25% in Candidate J’s four-agent environment) is selected by a dedicated seed. It keeps using the same productive PPO movement policy but may add false food pheromone at its actual occupied cell. The deposit is nonnegative, local, budgeted, capped, and evaporates like ordinary pheromone. It cannot remove a trail, alter food/reward, write elsewhere, or modify network weights.

Each policy/map pair is evaluated as a matched triplet:

ScenarioPurpose
CleanNo attacker is selected and no injection mechanism is present.
Injection disabledThe same seeded agent is selected as in the attacked twin, but it adds zero false mass. This controls for merely designating a worker as compromised.
AttackedThe selected agent can make the specified bounded false-food deposits.

The primary metric is injection loss:

injection loss = honest delivery(injection disabled) − honest delivery(attacked)
A positive value would mean injection reduced honest delivery. A zero or negative value does not support a reliable disruption claim.

The honest conclusion: these three persistent attack configurations were not shown to reliably harm Candidate J’s delivery. This does not prove false pheromone is harmless in all settings. It means there is not yet evidence strong enough to train/tune a detector or claim a defense works. A new attack-calibration decision is required before expanding the threat model.

What is inside the Phase 2B development corpus?

PartContainsWhy separated?
model_observableLocal observation, action, local-history features, and each agent’s own progress.These are the kinds of values a real local policy/detector could be allowed to use.
auditAttacker identity, attack events, requested/authorized/applied injected mass, and global/honest delivery accounting.Needed to audit simulation truth, but forbidden as model input because it would leak the answer.

A data leak happens when a model is given hidden information that would not be available at decision time. For example, handing a detector the attacker ID would make the evaluation unrealistic. The corpus builder fails if simulator-only attack fields appear in model-observable records.

Inspectable CSV export

The exporter produced a development-only table with 412,016 rows: one agent at one completed environment transition. It comes from 103,004 environment steps, 108 episodes, and 36 intact groups. The schema identifies 58 local-observation columns and 12 local-history columns as possible local inputs; it labels group/map/scenario/seed as provenance and actions/rewards/progress as outcomes.

This CSV is not a final machine-learning dataset. It has no temporal windows, train/validation/test partition, detector labels, fitted detector, or robustness result. Rows from related episodes must never be randomly mixed across future splits; complete policy/map/action/attack families stay together to avoid data leakage through correlated examples.
